# Synthetic threshold calibration

Item: [pm-jev-6uoz](../.agents/pm/issues/pm-jev-6uoz.toon).
This is an opt-in local evaluation tool. It never reads a tracker, consumes user
traces, trains a model, writes settings, or calls a hosted inference provider.

## Reproduce

```sh
npm ci
npm run calibration:generate
npm run calibration
# Explicit settings: model, loopback origin, report destination, target precision
npm run calibration -- tev1:4b http://127.0.0.1:11434 calibration/report-v1.json 0.95
# Bun can execute the same opt-in script.
bun run calibration
```

The generator accepts optional positional seed and output arguments. Its default
seed is 20261008. Template/label changes require incrementing
`pm-jev-calibration/1`. `calibration/dataset-v1.json` is generated byte-for-byte
from that seed with an unsigned 32-bit linear congruential generator. It contains
64 independent noul questions: 16 each for negations, numeric boundaries,
adversarial state, and long context. Each family has eight calibration questions
and eight held-out evaluation questions, with four true and four false labels
in each split. IDs are unique; calibration and evaluation use disjoint tokens
and boundary values. The generator knows labels from boolean facts and integer
comparisons; no model invents the ground truth. Long context places the current
fact before or after about 3,000 characters of archived distractors.

The harness refuses input that differs from the committed generator's output.
Only HTTP loopback origins and the local `tev1:0.8b`, `tev1:4b`, and `nimble:9b`
model names are allowed. Before inference, `/api/tags` must show an installed
model with a 64-digit digest, decision capability, and no remote-model fields.
The same digest is verified after inference. Redirects are refused. No credential
is read from the environment; the production client factory uses the SDK's fixed
local placeholder. Network calls comprise local inventory reads and the official
TypeSafe SDK's `/v1/systemone` calls through `runDecision`, including its response
validation, timeout, retry, and deadline behavior. A failure aborts the run before
writing a report; no successful report silently drops failed questions.

## Derivation

The fixed baseline decision is `probability >= 0.5`, including equality. Noul has
no SDK `confidence` field, so each observation records derived confidence as the
probability of the predicted label: `p` for true and `1-p` for false. This matches
the chosen-option probability meaning of the current min-confidence application
gate; it does not calibrate choice/score answers or their SDK confidence fields.

For each family and the pooled sample, the confidence reliability curve evaluates
all observed cutoffs plus 0 and 1. At every inclusive cutoff it reports accepted
count, correct count, coverage and selective precision (correct / accepted).
Tied confidences stay together. The recommended min-confidence is the lowest
cutoff achieving the declared empirical target precision (default 0.95), with at
least four accepted calibration observations. No qualifying cutoff yields null;
zero accepted observations have undefined precision, never perfect precision.

A separate gate curve evaluates observed noul probabilities plus 0, 0.5 and 1.
It reports true/false positives, false negatives, positive-class precision, recall
and accuracy. The family gate recommendation is the lowest cutoff meeting the
same target with at least four positive predictions. Positive-class precision
and selective correctness are different objectives: rejecting more propositions
can improve positive precision while reducing recall and increasing false
negatives. The report retains the whole curve to expose this trade-off.

Thresholds are fitted exclusively on the calibration split. Evaluation applies
the frozen cutoffs and also reports the 0.5 baseline. Confidence evaluation uses
the fixed baseline predictions, independently of the derived gate threshold.
`pooled.confidence.threshold` is the candidate common min-confidence default;
`families[*].confidence.threshold` and `families[*].gateThreshold` are per-family
candidates. They are advisory and are never installed automatically.

## Evidence boundaries

The committed report pins the dataset version, seed, SHA-256 of generated bytes,
requested and returned model names, installed model digest, time, duration,
usage, per-question probabilities/confidences/correctness, and every curve.
Regenerating the dataset is deterministic; rerunning inference is not promised
to be byte-identical. SDK retries can produce multiple attempts; token usage is
from the final validated responses.

Eight held-out questions per family cannot establish a population precision of
95%. Even eight successes out of eight have a one-sided 95% exact-binomial lower
bound of about 69%. The declared target is an empirical selection rule, not a
statistical guarantee. Shared templates, balanced labels, repeated distractors,
no real workload, no distribution-shift testing, and one model run limit transfer.
Long context here is bounded text, not a context-window stress test. Numeric
boundaries test a known model weakness and are not permission to delegate
arithmetic to inference. False positives and false negatives must remain visible.

The read-only pm-rl reference exposes public `EnvironmentSpec`,
`parseEnvironmentSpec`, and loop APIs. This harness does not fit a decision head
or create training generations, so it adds no pm-rl runtime dependency. A later
programme can register this versioned corpus and correctness reward through
pm-rl's public environment API and link the report digest as evaluation evidence;
no private pm-rl internals or writes to that checkout are involved here.

## Verification

`test/calibration.test.ts` runs deterministic local HTTP servers with the official
SDK, without Ollama. Tests cover generator reproducibility and balancing,
inclusive cutoffs, ties, insufficient support, null precision, held-out isolation,
positive-class metrics, inventory provenance, remote rejection, malformed answers,
model changes, and the opt-in script. Package coverage includes every authored
TypeScript source, including the harness and generator, at the unchanged 100%
thresholds. See the PR receipt below for the derivation revert proof and gates.

## Local measurement and PR receipt

[Committed report](../calibration/report-v1.json): `tev1:4b`, model digest
`9b5bb969e46c4b776826d6f2d401e22893205693f172653af6254897255025b8`,
recorded 2026-10-08. The run took 261,346 ms and answered 64/64 correctly:
32/32 calibration and 32/32 held-out. Every family scored 8/8 held-out,
100% selective precision and coverage, and 100% gate precision and recall.
All family gate recommendations and the pooled gate recommendation are 0.5.
All confidence recommendations are 0: accepting every observation meets the
empirical target on this perfect sample. These are results from one narrow
synthetic run, not evidence that every workload can safely accept all answers.
The defaults remain `gate_threshold=0.5` and `min_confidence=0.8`; no production
or choice/score evidence supports lowering the latter.

Revert proof command:

```sh
node --test --test-name-pattern='threshold derivation|family derivation' test/calibration.test.ts
```

Replacing derived confidence with the provisional constant 0.8 and derived gate
with 0.5 produced exit 1 and two assertion failures (`0.8 !== 0.7`). Independently
reverting only gate derivation produced exit 1 (`0.5 !== 0.7`). Source was restored
byte-for-byte and the focused command passed 2/2. No mutant is committed.

Required release checks run with unchanged 100% coverage thresholds and zero
allowed duplication: `npm run release:check` and `bun run release:check`, each
also under a disposable HOME with `GIT_CONFIG_GLOBAL=/dev/null` and
`GIT_CONFIG_NOSYSTEM=1`. `npm run changelog:full` regenerates the tracker-linked
changelog after pm mutations. No merge, publish or release is part of this work.
